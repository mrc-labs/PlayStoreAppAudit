## Six-target engineering assembly readiness

The v2.1 precedent must be used deliberately for the same unsigned/ad-hoc trust profile. `assemble-release.yml` requires signed Windows and production macOS; the Windows engineering workflow accepts x64 only. Preserve both contracts. The existing canonical `assemble_release_assets.py` and `release_asset_layout.py` support the six-target engineering input set and have targeted regression coverage; no new assembler or production-signing activation is needed.

At final assembly, query each accepted workflow run first and require the same repository, `workflow_dispatch`, completed/success, exact frozen head SHA, correct workflow identity, both architecture jobs passing and the expected exact artifact names. Download only those selected Windows/Linux runs and the macOS engineering run (whose Actions names have the `PlayStoreAppAudit-engineering-` prefix), retaining the canonical inner ZIP names and original legal staging. Verify inner `BUILD-INFO` version/source/full Python, package trust state, architecture, runtime/legal hashes and source checksums. Reject partial/failed runs or artifacts from another SHA. Then invoke the unchanged canonical helpers with the frozen SHA and version 2.2.0, require all platforms and exactly eight output files. Compare each copied binary ZIP with its input byte-for-byte and validate the consolidated source union and `SHA256SUMS.txt`.

This is the documented procedure for later final evidence, not authorization to assemble/tag/publish now. The final patch alignment also applies to the controlled local assembler environment. Linux compatibility reports are separate Actions artifacts and are not public release assets.
